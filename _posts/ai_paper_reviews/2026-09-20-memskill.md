## 0. Abstract

기존의 메모리시스템들은 add, update, delete, skip같은 사람이 설계한 기본연산을 사람이 만든 휴리스틱 기준에 따라 실행하는식으로 수작업 기반의 메모리 관리를 해왔다고 함.
근데 ADAS와 마찬가지로, 메모리 또한 수작업 feature engineering이 아니라 자동으로 학습되는 방식으로 가야한다고 주장함.

그래서 자동으로 학습되는 메모리관리시스템인 Memskill 이라는걸 만들었는데 controller, executer, designer 이렇게 세 파트로 구성됨.
executer는 정해진 스킬을 정직하게 수행해서 메모리를 채우는애라서 훈련이 필요하지않은 실행기임.
controller는 상황에따라 어떤 스킬을 사용해서 메모리를 채울지 정하는 지휘관같은 애고 RL로 훈련함.
designer는 스킬 자체를 새로 만들어내는애인데 신기하게 별도 훈련을 하지는 않는다고 함.

## 1. Introduction

![논문 Figure 1: (a) 기존의 턴 단위·수작업 연산 방식과 (b) MemSkill의 span 단위·skill 조건부 메모리 생성 방식 비교](/assets/img/ai_paper_reviews/Memskill/memskill-fig1.png)

대화기록에서 메모리를 추출하느

크게 자신들이 추구하는 에이전트 메모리시스템의 목표는

1. 메모리 연산(스킬)과 스킬 선택이 인간의 사전지식, 즉 휴리스틱에 최소한으로만 의존해야하고
2. 기존의 턴 단위 메모리추출은 너무 비효율적이라 더 긴 구간단위로 메모리추출을 수행할수 있어야하고
3. 묻지도 따지지도 않고 일률적인 파이프라인을 통과시켜서 메모리 추출하는게 아니라 그때그때 상황에 맞는 스킬들을 딱 사용해서 메모리추출을 해내야함.

그래서 기존의 굳어져있는 수작업 메모리연산은 designer를 통해 진화하는 skill bank로 업그레이드하고, 정적이고 일률적인 메모리연산 선택 전략은 controller가 동적으로 최적의 연산을 선택하도록 학습하게 업그레이드함.

## 2. Related work

Memskill은 LLM agent 메모리와 agent 자기진화분야의 교집합이라고 볼 수 있음.

### 2.1 LLM agent memory systems

기존 방법론들은 보통 주기적으로 일률적인 파이프라인을 통해 메모리를 추출하는 방법들이라고 함. 
최근 연구중에서 RL로 최적의 스킬을 선택해서 메모리추출을 하도록 학습시키는 방법(Memory-R1, Mem-⍺)들은 있었지만, 스킬 자체를 새로 만들어내려는 방법은 없었다고 함.

### 2.2 Self-evolving LLM agents

agent 자기진화분야도 다양한 계보들의 방법론이 있음.
reflexion처럼 과거 경험에서 자연어 피드백을 얻으며 스스로 발전해나가는 방향(ExpeL, EvolveR), 알파고-zero처럼 스스로 자기들끼리 대결하면서 발전해나가는 방향(Absolute zero, Multi-agent Evolve, R-zero), 에이전트 구조를 자동으로 설계하고 진화하는 방향(ADAS, Alpha evolve) 등이 있다고 함.
그리고 자기들이랑 가장 유사한 계보로, Skill weaver라는 연구가 스스로 스킬을 만들어내고 선택하는법을 학습하지만, 이건 웹 에이전트분야고 자기들은 메모리라는점에서 명확히 구분함.

### 3.1 Overview

Memskill의 핵심 프로세스는 스킬사용을 학습하는것과 skill bank를 업데이트하는 두가지로 분류됨.
저장소는 memory bank과 skill bank 2가지로 나뉨.

### 3.2 Skill bank

![ALFWorld에서 진화된 skill 예시 TRACK_OBJECT_MOVEMENTS - Purpose, When to use, How to apply, Constraints, Action type으로 구성](/assets/img/ai_paper_reviews/Memskill/memskill-fig3.png)

skill $$s\in\mathcal{S}$$ 는 이렇게 해당 skill에 대한 짧은 설명과, (목적, 사용시점, 사용방법, 제약조건)으로 이루어진 프롬프트 문서에 불과함.
처음에는 기본적인 메모리연산인 INSERT, UPDATE, DELETE, SKIP만 넣어주지만, 나중에는 실패사례를 바탕으로 새로운 skill을 만들어져서 추가된다고 함.

### 3.3 Learning to use memory skills

**3.3.1 Controller: skill selection policy**

먼저, 메모리를 추출할 때 어떤 skill을 사용할지 선택할때는 우선 지금 스텝 $$t$$의 내용을 chunking해서 텍스트 스팬 $$x_t$$로 만듦.
그리고 그 텍스트 스팬으로 memory bank에서 관련성이 높은 memory들을 $$M_t=\{m_{t,1},...,m_{t,R}\}$$ 이렇게 검색해옴.
그렇게 얻은 $$x_t$$, $$M_t$$를 인코딩해서 $$h_t=f_{\text{ctx}}(x_t,M_t)$$ 이런 현재의 상태 표현으로 만들어버림.
왜 $$M_t$$를 같이 넣어주냐면, 가령 $$x_t$$가 “아까 점심약속, 강남역말고 홍대입구로 하자” 라는 chunk라면, $$M_t$$에 “점심약속장소:강남역” 이라는 memory가 있으면 UPDATE를 해야겠지만 아무것도 없으면 INSERT를 해야하니까..

skill도 마찬가지로 skill의 설명부분(desc)만 인코딩해서 $$u_i=f_{\text{skill}}(\text{desc}(s_i))$$ 각 skill의 표현을 만듦.

마지막으로 상태와 skill의 표현을 만들었으니, $$z_{t,i}=h_t^\mathsf{T}u_i, \quad p_\theta(i\mid h_t)=\text{softmax}(z_t)_i$$ 이렇게 내적을 통해 Gumbel top-K로 상위 $$K$$개의 skill들을 선택함.
Gumbel top-K는 그냥 Gumbel 노이즈라는걸 더한 후 top-K를 하는거라고 하는데, 수학적으로 원래 확률대로 뽑는거랑 완전 동일한 결과가 나와서 반복없이 한방에 비복원추출할때 많이 쓴다고 함.
갑자기 skill notation을 $$A_t=(a_{t,1},...,a_{t,K})$$ 이렇게 아무 언급없이 바꾸던데, preprint라 이런 실수 하는듯.
그리고 인코더가 훈련되는줄 알았는데, 저~ 뒤에서 MLP를 이용해서 

어쨌든 이런식으로 현재 step의 텍스트 스팬 $$x_t$$에 대한 메모리를 추출할 때 어떤 skill들을 사용할지 정할 수 있음.

**3.3.2 Executor: skill-conditioned memory extraction**

[행동: 전자레인지 열기, 제약조건: 잠겨 있음, 필요조건: 회색 열쇠], [사용자는 다음 주 월요일부터 금요일까지 도쿄에서 열리는 AI 컨퍼런스에 참석할 예정임] 이런식의 짧은 자연어문장을 추출해서 memory bank에 넣는 역할.
입력으로 텍스트스팬 $$x_t$$, 검색된 기존메모리 $$M_t$$와 스킬 $$A_t$$를 받음.
추출할 대상인 $$x_t$$랑 스킬 $$A_t$$만 있으면 되는거 아닌가 싶었는데, UPDATE나 INSERT같이 기존 메모리가 필요할때가 있어서 $$M_t$$를 추가로 넣어줘야하는듯.

**3.3.3 Controller optimization**

controller를 훈련할때는 RL를 사용하는데, Memskill로 구축된 memory bank를 가지고 downstream task를 수행했을때의 성능을 보상으로 사용한다고 함.
아마 인코더를 통과한 원시표현을 어떻게 변환시킬지 훈련시키는듯.

controller에서 skill $$K$$개가 나오니까 정책을

$$
 \pi_\theta(A_t\mid s_t)= \prod_{j=1}^K \frac{p_\theta(a_{t,j}\mid s_t)}{1-\sum_{\ell<j}p_\theta(a_{t,\ell}\mid s_t)}
$$

이렇게 결합확률(비복원추출 가정)로 나타냄.
하나 헷갈렸던게, ‘아니 학습가능한게 MLP뿐이니까 정책은 MLP 아닌가? 왜 정책에서 $$K$$개가 나온다는거지? 그건 뒤에있는 내적이랑 소프트맥스 top-K에서 나오는데?’ 싶었음
근데 강화학습에서 정책은 $$s$$를 넣었을때 $$a$$를 출력해주는 애를 통으로 말하는거라 인코더-MLP-내적-소프트맥스-top-K가 한덩어리로 정책이고, 유일하게 훈련가능한 MLP는 정책의 파라미터라고 부름.

그리고, 문서의 chunk 단위로 action이 진행되니까, 메모리 추출은 여러 스텝에 걸친 에피소드이고 마지막 스텝에서만 보상이 나오는 설정으로 볼 수 있음.

### 3.4 Skill evolution through designer feedback

Hard-case buffer 라는곳에 틀린문제들 집어넣는데, 쿼리와 정답, 검색된 메모리, 메타데이터같은 정보들을 집어넣는다고 함.
그리고 너무 오래된 데이터는 자동으로 삭제함.

여기서 designer에게 실패사례를 줄때는 쿼리들의 의미적 유사성에 따라 먼저 클러스터링하고, 자기들이 만들어놓은 간단한 휴리스틱점수로 각 클러스터별로 실패사례들을 뽑아서 준다고 함.

## 4. Experiments

### 4.1 Experiment setup

RL로는 PPO를 사용하며, 메모리 검색기로는 Contriever를 사용함.
executor랑 designer로는 LLaMA-3.3-70B-Instruct 사용.
controller의 임베딩 모델로는 Qwen3-Embedding-0.6B 사용.

designer는 100 controller training step(청크별로 메모리 추출하는 step 아닌듯)마다 사용된다고 하고, 한번에 3개의 skill까지 편집할수 있다고 함.

베이스라인으로는 

No-memory: 그냥 일반 LLM

Chain-of-Notes: RAG인데 검색된 문서에대한 요약을 먼저 스스로 작성하고 그걸로 이용해서 답변 생성

ReadAgent: 문서에 목차가 달려있어서 목차를 보고 쿼리에 맞는 문서를 찾아보고 대답하는 느낌.

MemoryBank: 사람처럼 시간이 지나면 까먹는데 반복적이고 중요한 기억은 강화되는 알고리즘

A-MEM: 문서(메모리)를 그래프방식으로 저장해놓는 방식

Mem0: add, update, delete, skip으로 메모리 저장하는 대표적인 방법인듯

LangMem: Mem0의 Langchain 버전인데 메모리에서 행동지침까지 뽑아낼수 있다고 함.

MemoryOS: 컴퓨터처럼 기억을 작업기억(RAM), 일회적 기억(캐시), 의미적기억(하드)로 구분하고 관리하는 시스템을 만듦.
