## Motivation

![논문 Table 1: embodied navigation용 object-driven 데이터셋 비교 - photo-realistic 장면·타겟, 추가 객체, 시각·서술 참조, 가변 배치, instance goal 지원 여부 (PInNED만 모두 충족)](/assets/img/ai_paper_reviews/PIN/pin-fig1.png)

**PointNav** — 좌표찍기: "현재 위치에서 (3m 앞, 2m 왼쪽) 좌표로 가라." 좌표만 찍으면 돼.
**ObjectNav** — 객체 찾기: "의자 찾아가." 카테고리만 주어지고, 환경에서 아무 의자나 찾으면 성공.
**ImageNav** — 특정 위치에서 찍은 사진 한 장을 주고 "이 사진이 찍힌 위치로 가라."
**InstanceImageNav** — "이 특정 물건 찾아가" + 물건이 환경에 놓인 상태의 사진을 줌.
기존에도 이런식으로 가정집을 navigation하는 embodied agent 벤치마크들이 있었음. 
근데 보면, 한가지씩 나사가 빠진부분들이 많았음.

가장 PIN이랑 유사한게 InstanceImageNav라는건데, 이건 실제 가정집을 3D스캔해서 만든 벤치마크라서 스캔시점에 실제로 집에 있던 object를 찾게함.

근데 문제가, 그럼 object가 3D가 깨진것도 많고 위치가 고정되어있어서 뭐 추가나 이동을 못함.
게다가 찾아야될 대상 이미지를 줄때 배경이 포함되어있어서 주변힌트를 악용할수도 있음.

그래서 PIN은 깨끗한 object를 랜덤하게 매번 바꾸면서 여러장소에 두고, 찾아야될 대상도 자연어 text로 되어있거나 배경없이 딱 object만 있는 사진을 주는방식으로 바꿈.
거기다가 더 헷갈리게 하는 distractor시스템? 도 추가됨.

“코부분이 하늘색인 테디베어를 찾아줘”나, 자세한 사진을 보여주고 찾게하는데, 사실 논문에는 PIN이 Personalized Instance… 라고 되어있지만 사실 뭐 진짜 사용자 상호작용으로 진짜 개인화를 한다기보다는 그냥 자세하게 물체를 식별하는 벤치마크라 Personalized라는 말은 잘 안어울리는듯.

## PinNED overview

![논문 Figure 1: PIN task 소개 - 테디베어의 시각 참조 3장과 텍스트 참조 3개가 주어지고, 에이전트가 같은 카테고리 및 다른 카테고리 distractor들 사이에서 타겟 인스턴스를 찾아감](/assets/img/ai_paper_reviews/PIN/pin-fig2.png)

HM3D라는 실제 주거공간 3D맵의 180개 씬에 Objaverse-XL이라는 3D물체 데이터셋에서 18개 카테고리에 걸친 338개의 객체를 가져와서 뿌림.
규칙기반으로 말이 되는 범위 안에서 에피소드마다 무작위적으로 뿌림.
훈련에피소드가 145개의 씬, 검증에피소드에 35개의 씬을 차지하고, 객체는 어떻게 분배됐는지 안나옴.

이때는 맞춤 모델을 만들어놓고 쓰는 방식을 썼어서 벤치마크지만 먼저 훈련시켜야했음.
그래서 훈련에피소드 865.5k개, 검증에피소드 1.2k로 나누어져 있는거임.

그리고 찾아야될 대상은 이미지 / 자연어 중 하나로 주어지는데, 먼저 이미지는 (측면, 후측면, 윗면이미지) 이렇게 3개가 주어지고, 자연어는 한 인스턴스에 대해 인간이 직접 만든 3가지 서로다른 설명중 보통 하나만 줌.

## Baselines

에이전트는 Modular agent와 end-to-end로 분류됨

#### **Modular agents**

탐험, 탐색, 탐지 모듈로 구성되어있음. 
탐지모듈은 인스턴스와 대상 인스턴스를 비교하는 역할을 하고, 탐험과 탐색모듈은 이동을 담당함.

탐지모듈은 크게 SuperGLUE, IEVE같은 key point-matching, DINOv2나 CLIP같은 patch level matching, OWL이나 PerSAM같은 detection model(YOLO류) 계열로 나뉨.
탐험모듈은 크게크게 안가본데를 이동하고, 탐사는 대상을 감지했을때 구체적으로 어떻게 움직일지 국소적으로 이동하는걸 담당.
근데 탐험과 탐색은 신경망모델이 아니라 그냥 최단경로탐색같은 규칙기반의 수학적 알고리즘이라고 함.

#### End to End agents

ZSON과 RIM이라는 방법이 있고, 에이전트의 관측이미지랑 대상을 인코딩해서 넣어주면 바로 action을 출력해주는 방식. 
feature형식으로 입력을 넣어주면 policy가 적합한 행동을 출력하도록 RL로 학습시킴.

![논문 Table 2: HM3D 환경의 PInNED에서 Modular agent와 End-to-end agent들의 navigation 지표(SR, SPL, CE, D2G, Steps)와 detection 지표(%Match, TM, CM, NM)](/assets/img/ai_paper_reviews/PIN/pin-fig3.png)

SR: 성공률, SPL: 거리 효율 고려한 성공률, CE: 같은카테고리 distractor에 멈춘 비율, D2G: 정답까지의 거리

%match: 찾았다고 주장한 에피소드 비율, TM: 그게 진짜 정답인 비율, CM: 그게 같은 카테고리 distractor였던 비율, NM: 둘다 아니었던 비율
