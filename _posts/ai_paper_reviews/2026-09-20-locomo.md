## Motivation

날씨확인이나 코딩돕기처럼 목표가 정해진 애들을 task oriented으로 분류하고, 평소에 우리가 챗봇 쓰는것처럼 일상적인 대화를 하는건 open domain으로 분류함.

open domain 대화에서는 세션간의 연결고리도 잘 기억하고있는것이 중요한데, 기존의 long-term open domain 대화를 평가하는 벤치마크는 고작 5개 이하의 세션들만 제공해서 제대로 평가를 할수 없었다고 함.
long-term은 세션간의 시간적 간격이 긴 경우를 의미하는건데, 대화 덩어리가 수십 수백개가 쌓이고 토큰이 수천 수만개가 쌓일때 과거의 특정 정보를 얼마나 정확히 낚아서 현재 맥락에 녹일수 있는지를 보는 환경.
한 세션내에서 턴이 몇개인지는 long-context이라서 다른 개념이라고 함.

그래서 자기들은 LoCoMo라는 방대한 long-term open domain 벤치마크를 만들었음.

기존의 Long-term dialogue를 다루는 방법론들은 보통 메모리를 검색해와서 추론하거나 중요 이벤트를 그래프로 표현하는 방식으로 접근했다고 함.
근데 일단 이런 방식의 문제점으로는 검색정확도가 높지 않다는거임.

```
네이트: 나 어제 월마트가서 새 사료 샀어
조안나: 오, 맥스가 잘 먹어?
네이트: 응 그거 줬더니 그릇을 싹 비우더라구(Golden)

Query: 맥스는 어제 산 사료 잘 먹었어?
```

이 상황에서도 Query 임베딩과 Golden 임베딩이 멀다고 판단해서 Golden을 놓치는 참사가 벌어짐…

또, 검색성능이 좋지 않아서 양치기로 해결해보려고 문서를 무작정 많이뽑아주면, noise(잡 문서)도 많이 섞이고, 중간에 있는 문서는 잘 소화하지 못한다는 문제가 있음.

```
Query: 조안나는 지금 개를 키워?

검색된 문서1: 예전에 미시간에서 개를 키웠었어
...
검색된 문서7: 알레르기때문에 보냈어
```

그리고 잘 뽑아줘도 검색된 문서를 가지고 인과관계를 추론하는것도 잘 못한다고 함.

```
예시: "나 어제 발목 접질렸어"
"아직 많이 부어 있겠네요. 조심하세요." (정상)
예시: "나 3개월 전에 발목 접질렸어"
"아직 많이 부어 있겠네요. 조심하세요." (오답: 보통 3개월이면 다 나았을 시간임을 인지해야 함)
```

마지막으로, 시간 흐름에 따른 적절한 응답 생성도 잘 못한다고 함.

자기들 벤치마크는 기존 방법들이 잘 못하는 한계점들을 제대로 보여준다는 빌드업.

## LoCoMo 개요

![논문 Figure 2: 평가 프레임워크 개요 - (1) Question Answering(Single-Hop, Multi-Hop, Temporal, Commonsense, Adversarial), (2) Event Summarization, (3) Multimodal Dialog Generation](/assets/img/ai_paper_reviews/LoCoMo/locomo-fig1.png)

LoCoMo는 서로다른 인물들간의 50개의 dialogue로 이루어졌고, 각 dialogue는 시간의 흐름으로 구분된 평균 19.3개의 session으로, 각 session은 평균 15.8 턴으로 이루어져있음.
그래서 각 dialogue는 평균 300턴이고, 토큰은 평균 9000토큰정도라고 함.
대화들은 먼저 정교한 설정이 주어진 LLM끼리 대화하도록 하고, 그걸 사람이 수정하는식으로 합성함.

또, 과제도 QA과제(평균 150문제), 요약과제, 멀티모달생성과제 이렇게 3가지 종류로 나눠져있는데, 요즘은 LoCoMo에서 사실상 QA만 쓴다고 함.
특히 QA과제는 내부에 또 Single-hop, Multi-hop, Temporal, Open domain, Adversarial 이렇게 다시 5가지 유형으로 나뉘어있음.

대화 데이터는 가상에이전트 2개를 만들고 서로 대화한 후 사람이 수정하는방식으로 합성하고, 가상에이전트는 페르소나와 이벤트그래프를 기반으로 대화하게됨.

```
페르소나 시드: "나는 개를 좋아해. 요리사로 일하고 있어. 최근에 이태리로 여행을 다녀왔어.”

확장: "32세 요리사 '마크'는 밀라노의 작은 식당에서 3년간 수습 과정을 거쳤다. 그는 매일 아침 에스프레소를 마시며 하루를 시작하고, 최근에는 자신의 레스토랑을 차리기 위한 자금을 모으고 있다. 골든 리트리버 '버디'를 키우고 있으며, 개 알레르기가 있는 사람과는 대화할 때 조심하는 편이다."
```

먼저, MSC데이터셋에서 짧은 페르소나 시드를 가져와서, LLM $$\mathcal{M}$$을 프롬프팅해서 더 풍부하고 구체적인 페르소나 $$p$$로 확장하도록 함.


그리고 그렇게 얻은 페르소나 $$p$$를 LLM에 넣고, 그래프 $$\mathcal{G}$$를 생성하게 함.
그래프 $$\mathcal{G}$$는 이벤트 $$e_i$$, 날짜 $$t_i$$ 인과관계 $$l$$로 이루어진 JSON 리스트에 불과함.
이때, 한번에 많은 사건의 인과관계가 정확히 유지되게 그래프를 만드는게 어려우므로 몇개의 기초사건을 먼저 만든 후 거기서 출발해서 조금씩 확장해나가는 방법을 사용한다고 함.

이제 이렇게 고생해서 만든 페르소나 $$p$$와 그래프 $$\mathcal{G}$$를 가지고 에이전트끼리 대화를 시킬건데, 인간의 장기, 단기 기억을 벤치마킹한 ’스탠퍼드 가상마을 에이전트’ 의 구조를 따라 몇가지를 더 넣어줘야함.

```
raw: "와, Nate! 첫 우승 축하해! 그 게임 이름이 뭐야?" 
observation: "Nate는 지난주에 첫 비디오 게임 토너먼트에서 우승했다."
```

각 세션을 $$k$$로, 세션의 각 턴은 $$k_j$$로 표시함.
각 세션의 대화내용은 $$h_k$$, 세션의 각 턴 대화내용은 $$h_{k_j}$$로 표시하는데, 이때 턴의 대화정보를 $$h_{k_j}$$이렇게 raw 형태로 바로 저장하는게 아니라 $$o_{k_j}$$ 이렇게 증류된 형태로 저장함.
각 세션의 요약본은 $$w_k$$으로 표시하는데, 이건 서사적 연속성을 위해 $$h_k$$뿐만 아니라 이전 세션 요약 $$w_{k-1}$$도 같이 보고 적음.

단기기억 $$\mathcal{H}_s$$은 직전 세션의 요약본인 $$w_k$$가 임시적으로 머무는 버퍼임.
장기기억 $$\mathcal{H}_l$$은 dialogue의 전체 기록에서 나온 정보를 담는 데이터베이스로, 관찰 $$o_{k_j}$$과 과거세션들의 요약본 $$w_{<k}$$ 들이 저장됨.

$$
\text{Response} = \mathcal{M}(p, \{e \in \mathcal{G}\},w_k, h_{k+1},o)
$$

그래서 최종적으로는, 응답을 생성하는 에이전트는 이렇게 다양한 입력을 받아 응답을 생성함.
에이전트의 페르소나 $$p$$, 이벤트 $$\{e \in \mathcal{G} \}$$, 직전세션 요약 $$w_k$$, 현재 세션기록 $$h_{k+1}$$, 관찰 $$o$$가 들어감.
관찰 $$o$$는 논문엔 정확히 안나오지만 방금턴의 상대 질문을 쿼리로 사용해서 검색해오는것같음.
그리고, 대화를 진행하는 주제인 이벤트는 $$\{e\in\mathcal{G} \mid t_k^s<t_i^e<t^s_{k+1}\}$$ 이렇게 이전세션 이후와 현재세션 이전에 발생한 이벤트를 사용하도록 함.
그렇게 하면 개인의 페르소나를 유지하고 실제 인과적인 이벤트를 잘 반영하면서도 이전세션의 맥락과 장기기억을 활용해 자연스러운 대화를 하는 에이전트가 만들어짐.
에이전트는 $$\mathcal{L}_1,\mathcal{L}_2$$ 이렇게 두개지만, 딱 세션기록 $$h_{k+1}$$만 공유하지 다른건 전혀 공유안함

![논문 Figure 11: 주석자의 수정 예시 - 관련 없는 이미지 제거·교체, 일관성 없는 대화 수정, 이벤트 그래프에 맞게 대화 수정](/assets/img/ai_paper_reviews/LoCoMo/locomo-fig4.png)

이후 사람이 생성된 대화내용중 어색한부분을 수정하는방식으로 dialogue 데이터셋 완성.
약 dialogue의 15%정도에 손을 댔어야했다고 함.

## LoCoMo 평가 벤치마크

이제 이렇게 만든 dialogue 하나를 넣어주고, 그 dialogue에 대한 task를 시킴.

기존 평가지표로는, 기계적인 어휘중복을 보는 BLEU는 의미적으로 맞는데도 잘 채점을 못하고, 의미의 ‘표면적’ 유사도를 보는 BERTscore로는 사실관계가 틀려도 문장구조가 비슷하면 의미가 비슷하다고 보는 문제가 있었음.
그 외에도 일관성, 모순, 공감 등을 보는 평가지표가 있었지만, 장기적인 맥락의 이해도를 평가하는데는 턱없이 부족해서 자기들이 평가지표도 좀 손봐서 씀.
