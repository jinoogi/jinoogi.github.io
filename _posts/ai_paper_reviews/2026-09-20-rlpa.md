## 0. Abstract

기존의 LLM 개인화 방법론들은 보통 프롬프트 기반 방법과 off-line 방법론을 사용하는경우가 많아 동적인 상황에 작동하지 못한다고 함.

그래서 자기들은 개인화 모델을 학습하는 RLPA라는 RL 방법론을 제안하는데, reward가 기존의 response reward에 profile reward라는 보상을 더한 이중보상구조임.
이렇게 했더니 개인화에서 SOTA를 찍었고, 프론티어모델들보다도 성능이 좋게나왔다는 이야기.

## 1. Introduction

![논문 Figure 1: 개인화 정렬 패러다임 비교 - (a) 프롬프트 기반 방법, (b) SFT·DPO 같은 오프라인 최적화, (c) 멀티턴 상호작용을 강화학습으로 최적화하는 RLPA](/assets/img/ai_paper_reviews/RLPA/rlpa-fig1.png)

기존의 프롬프트기반 방법론은 사용자정보를 컨텍스트에 넣는 방법이기때문에 개인화가 얕은수준으로만 가능하고, off-line 방식인 SFT/DPO는 학습할때 못본 유형은 사용자에는 잼병이라고 함.

이런 일종의 OOD문제를 콜드스타트문제라고 하는데, “그건 그냥 DPO 학습데이터를 제대로 못만들어서 그런거 아니야? 시뮬레이터로 다양한 traj를 합성해내면 되는거잖아?” 싶었음.
그건 맞는데, 그렇다고 해도 DPO는 single turn에만 맞춰져있어서 장기적인 전체 traj의 보상을 최대화하지는 못한다고 함.
DPO수식을 다시 봤더니 목적함수도 수익(누적보상) $$G_t$$ 가 아니라 한 스텝의 보상 $$r_t$$ 최대화로 맞춰져있고, 그 목적함수를 끼우는 BT보상모델도 한 스텝의 응답을 보고 선호를 선택하게되어있었음.
결국 DPO는 우리가 아는 일반적인 traj를 고려한게 아니라서 장기적인 개인화를 위해서는 버려야함.

그렇게 하기 위해서 자기들은 개인화문제를 여러 스텝에 걸친 multi-turn MDP로 정의하고, 그냥 답변품질 정렬이 아니라 개인화까지 달성하기 위해 Profile reward와 Response reward로 이루어진 이중보상을 사용해서 모델을 학습함.

## 2. Preliminaries

### 2.1 Personalized alignment as a multi-turn markov decision process

- $$\mathcal{S}$$: 상태는 $$s_t=\{u_1,r_1,...,u_t\}$$ 이렇게 사용자와 에이전트간의 대화기록으로 표현함.
 특이하게도 여기서는 $$r_t$$를 에이전트의 응답을 나타내는데 사용하고, $$u_t$$는 사용자의 발화임.
- $$\mathcal{A}$$: $$a_t$$로 표시하는데 $$r_t$$랑 똑같은거임.
- $$\mathcal{T}$$: 상태전이확률
- $$\mathcal{R}$$: $$R_t$$로 표시함
- $$\gamma$$: $$\in[0,1]$$ 의 할인률

### 2.2 Reinforcement learning for policy optimization

이제 진짜 multi-turn MDP니까 목적함수는 $$J(\pi)=\mathbb{E}_\pi\bigg[ \sum_{t=1}^T \gamma^{t-1}R_t\bigg]$$이렇게 누적보상의 최대화로 설정.

## 3. RLPA: Reinforcement learning for personalized alignment

![논문 Figure 2: RLPA 프레임워크 개요 - 정책 모델이 매 턴 추론한 프로필과 응답을 내고, Profile Reward와 Response Reward 두 보상으로 평가받음](/assets/img/ai_paper_reviews/RLPA/rlpa-fig2.png)

모델은 정책모델, 사용자모델, 보상모델 이렇게 3개가 필요함.
정책모델 $$\pi(a_t\mid s_t)$$은 Qwen-2.5-3B-Instruct를, 사용자모델 $$\pi_u(u_{t+1}\mid H_t,P)$$은 GPT-4o-mini를, 보상모델 $$R_t$$도 GPT-4o-mini를 사용했다고 함.

자기들 방법인 RLPA의 핵심적인 차별요소 3가지로는 사용자모델 $$\pi_u(u_{t+1}\mid H_t,P)$$, 프로필 보상함수 $$R_t^{\text{profile}}$$, 응답 보상함수 $$R_t^{\text{response}}$$ 라고 함.

### 3.1 Simulated user design

![논문 Figure 7: 사용자 프로필 슬롯 예시 (영어, 중국어) - Age, Gender, Interests, Educational Background, Personality Traits, Occupation 등](/assets/img/ai_paper_reviews/RLPA/rlpa-fig3.png)

사용자모델을 만들때는 먼저 사용자 프로필을 주는데, 나이:25세, 학력:대졸, 흥미:캠핑 … 이런식의 정보를 줌 
 $$P=\{p_1,p_1,...,p_n\}$$ 이런식으로 표현됨.
그리고 대화기록 $$H_t=\{u_1,r_1,...,u_{t-1},r_{t-1}\}$$도 같이 넣어서 결과적으로 $$\pi_u(u_{t+1}\mid H_t,P)$$ 를 만듦.

$$H_t$$는 $$s_t$$랑 똑같은건데, $$s_t$$는 정책입장에서 바라본거라서 사용자 입장에서 바라보는 대화기록임을 강조하기 위해서 저렇게 표현하는듯.

중요한건, 저 사용자모델 $$\pi_u$$가 프로필 $$P$$에 기반해 일관적으로 행동하고, 프로필을 한번에 추론할수 있게 힌트를 왕창 내놓는게 아니라 턴이 진행되어가면서 조금씩조금씩 내놓는다고 함.

### 3.2 Profile reward function design

![논문 Figure 12: actor 모델의 시스템 프롬프트(영어판) - 먼저 profile 태그 안에 사용자 프로필을 추론하고 response 태그 안에 개인화된 응답을 쓰게 함](/assets/img/ai_paper_reviews/RLPA/rlpa-fig4.png)

정책모델이 사용자 프로필을 정확히 추론할때 주는 보상을 설계함.
정책모델이 답변을 생성할때 먼저 &lt;profile&gt;&lt;/profile&gt; 안에 자기가 추론한 사용자 프로필 $$\hat{P}$$ 를 채워넣는데, 

$$
R_t^{\text{profile}}=\frac{2\cdot \text{Precision}_t\cdot \text{Recall}_t}{\text{Precision}_t+\text{Recall}_t}=\frac{2\cdot|\hat{P}_t\cap P|}{|\hat{P}_t|+|P|}
\\
\text{where} \quad \text{Precision}_t=\frac{|\hat{P}_t\cap P|}{|\hat{P}_t|}, \quad\text{Recall}_t=\frac{|\hat{P}_t\cap P|}{|P|}
$$

이렇게 간단하게 프로필요소별 recall과 precision으로 보상함수를 정의했고, 자연어 생성기반이다보니 규칙기반으로는 채점할수가 없어서 보상모델을 이용해서 일치하는지 채점해달라고 함.

### 3.3 Response reward function design

논문에는 먼저 4가지 기준을 고려해서 스칼라점수를 내고, 5가지의 이진기준까지 추가적으로 만족해야 점수를 주는것처럼 적어놨는데 실제로는 그냥 이진기준만 사용해서 $$R_t^{\text{response}}=N\cdot R \cdot L \cdot G \cdot F$$ 이런식으로 0 아니면 1인 이진보상을 줌…
각 이진기준은 자연스러움, 관련성같은 이준으로, 보상모델에게 판단을 맡김.

### 3.4 Training with PPO

만들어놓은 사용자 프로필 보상과 응답 보상을 $$R_t=R_t^{\text{profile}}+R_t^{\text{response}}$$ 이렇게 합치고, PPO 목적함수 

$$
\mathcal{L}^{\text{PPO}}(\theta)=\mathbb{E}_t\Big[\min\Big(r_t(\theta)\hat{A}_t, \text{clip}(r_t(\theta),1-\epsilon,1+\epsilon)\hat{A}_t\Big)\Big]
$$

를 이용해서 훈련을 진행함.
LLM 강화학습돌릴땐 PPO-ptx term 넣어야하는데, 언급이 없음.
OpenRLHF라는 프레임워크 사용해서 자동으로 그렇게 처리해준듯.

## 4. Experiments

### 4.1 Experimental setup

정책모델은 Qwen-2.5-3B-Instruct, 사용자모델과 보상모델은 GPT-4o-mini를 썼다는 내용.

프롬프트 기반의 베이스라인으로는 Reminder, self-critic, CoT, RAG를 선택했고, offline 최적화 기반의 베이스라인으로는 SFT와 DPO를 사용했다고 함.
다만, 원래 논문에서 저격했던 프롬프트기반의 방법은 사용자 프로필을 프롬프트에 넣어주는 방법들이었던데 비해 여기서는 프로필을 넣어주지 않는 프롬프트기반의 방법들을 베이스라인으로 사용함. 쫄렸나?

- Base: 아무 추가 instruction없이 그냥 사용자의 질문에 대답하게하는 방법
- Reminder: 대답하기전에 사용자 취향을 반영해서 대답하라는 프롬프트 한줄 추가된거.
- Self-Critic: 생성한 응답이 사용자 취향을 잘 반영했는지 한번 스스로 자아비판하고 개선하는 방법
- CoT: CoT Few-shot 5개 제공
- RAG: 관련 대화기록 5개 제공하고 취향 반영하게 함
- SFT: 모범 데이터로 지도학습
- DPO: 선호비교로 최적화

![ALOE 논문의 개요 그림: 기존 방식(Previous Work)과 페르소나 풀·추론된 페르소나를 이용해 멀티턴 선호 데이터를 만드는 방식(Our Work), 그리고 데이터 구조](/assets/img/ai_paper_reviews/RLPA/rlpa-fig5.png)

벤치마크로는 ALOE라는 페르소나 데이터셋을 사용함.
채점과정이 상당히 지랄맞은데, 먼저 각기 다른 프로필들을 이용해서 74명의 사용자 모델을 만들고, 10턴으로 구성된 74개의 대화를 진행함.
매 턴 LLM Judge가 사용자 정답프로필, 대화기록, 에이전트의 응답 $$r_t$$를 받아 얼마나 잘 정렬된 응답을 출력하는지 평가하는데, $$k$$번째 턴에서 여러 페르소나간의 평균적인 align level을 $$\text{AL}(k)$$라고 함.

$$
\text{N-AL}(k)=\frac{\text{AL}(k)-\min_{i=1,...,k}\text{AL}(i)}{\max_{i=1,...,k}\text{AL}(i)-\min_{i=1,...,k}\text{AL}(i)}
$$

그리고 저걸 정규화한 걸 $$\text{N-AL}(k)$$라고 하고, 이것의 선형회귀 상관계수 $$\text{N-R}^2$$과 기울기(improvement rate) $$\text{N-IR}$$ 를 성능지표로 사용함.

### 4.2 Overall results

![논문 Table 1: Vanilla ALOE와 Extended ALOE에서의 개인화 정렬 성능 - 평균 정렬 점수, N-IR, N-R² (프론티어 모델 Self-Critic, Qwen2.5-3B 기반 baseline들, RLPA)](/assets/img/ai_paper_reviews/RLPA/rlpa-fig6.png)

Vanilla는 학습과 검증 모두 속성 유형은 동일하게 유지되지만 속성값은 달라지는 케이스, Extended는 속성 유형도 달라지는케이스임.
실험결과를 보면, RLPA가 다른 방법론들을 압도하고 심지어 Self-critic 적용한 프론티어 모델들보다도 잘하는걸 확인할 수 있음.

![논문 Figure 3: Extended ALOE에서 턴별 정렬 점수 - (a) SFT, (b) DPO, (c) Self-Critic은 턴이 지날수록 떨어지고 (d) RLPA는 꾸준히 상승](/assets/img/ai_paper_reviews/RLPA/rlpa-fig7.png)

그리고, 본게임으로 진짜 offline 라이벌인 SFT와 DPO와도 겨루는데, SFT나 multi-turn MDP를 고려하지 않고 만든 DPO는 턴이 지남에 따라 오히려 점수가 내려가지만 RLPA는 정석적인 multi-turn MDP상황을 가정하고 훈련해서 턴이 늘수록 점수가 우상향하는것을 확인할 수 있음.

사용자 선호가 동적으로 변화하는 상황을 모델링한건데, 실제 사용자의 선호는 상황에 따라 변할때가 많아서 이게 진짜 실전적인 세팅같음.

### 5.3 Stable profile modeling in long-term interaction

얼마나 긴 multi-turn 대화에도 적응할 수 있는지 보기위해 10턴이 아니라 아예 70턴을 돌리면서 profile 점수를 추적함.
사용자정보를 서서히 흘리기때문에 이론적인 최대치가 있는데, 턴이 길어져도 점수가 계속 올랐고 거의 이론적인 상한점을 계속 찍었다고 함.

이 논문의 실험에서 SFT(지도 미세조정)와 DPO(직접 선호도 최적화)로 학습된 모델들은 대화 초반(약 1~5턴)에는 어느 정도 점수를 유지하다가, 6~10턴으로 대화가 길어지면 평균 정렬 점수가 수직으로 추락하는 현상(Figure 3)을 보였습니다. 이 모델들이 대화 후반부에 점수가 급락하는 근본적인 이유는 무엇일까요?

A1: DPO는 single-turn을 기준으로 만든 방법임.
그래서 애초에 지금 다루는 실전적인 개인화 응답문제처럼 multi-turn 상황에서는 태생이 안맞고, 어거지로 여러 turn의 입력을 쑤셔넣어준다고 해도 짧을땐 그래도 어느정도 하는것같다가 길어지면 본색이 드러남.

SFT는 지도학습이라 태생이 이런 복잡한 trajectory를 고려해야하는 multi turn task과 안 어울림.

문제 2. 이중 보상 구조 (Dual-level Reward) 
RLPA 프레임워크는 에이전트를 훈련시킬 때 '프로필 보상(Profile Reward)'과 '응답 보상(Response Reward)'이라는 두 가지 보상을 동시에 줍니다. 만약 훈련 과정에서 '프로필 보상(Profile Reward)'을 아예 빼버리고 '응답 보상(Response Reward)'만 주면서 훈련시킨다면(Ablation Study), 모델의 대화 궤적이나 성능에는 어떤 문제가 발생할까요?

A2: 그렇게되면 사실 시뮬레이터가 있는 일반 RL과 다를바 없을듯.

문제 3. 새로운 평가 지표의 존재 이유 (N−IR,N−R^2) 
저자들은 에이전트를 평가할 때 단순히 1~10턴의 평균 점수(AVG)만 보지 않고, 굳이 점수들을 N−AL이라는 0과 1 사이의 값으로 정규화(Normalization)한 뒤에 N−IR(향상률)과 N−R^2(안정성)라는 지표를 계산했습니다. 단순히 평균 점수만 쓰지 않고 이 복잡한 정규화 과정을 거친 이유는 무엇일까요?

문제 4. 가상 사용자(시뮬레이터)의 연기 규칙 
공정한 콜드 스타트(Cold-start) 평가를 위해, 저자들은 가상 사용자 역할을 맡은 GPT-4o-mini의 프롬프트에 아주 엄격한 행동 규칙들을 지시했습니다. 그중 하나인 "정보 점진적 공개 메커니즘(Progressive Information Disclosure Mechanism)"은 한 번의 대답에서 프로필 정보의 15% 이하만 흘리도록 제한하고 있습니다. 만약 이 규칙이 없어서 가상 사용자가 첫 턴부터 자신의 취향을 줄줄 다 말해버린다면, 이 벤치마크 평가에는 어떤 치명적인 문제가 생길까요?
