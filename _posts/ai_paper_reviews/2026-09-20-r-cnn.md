## 0. Abstract

![Classification, Localization, Object Detection, Instance Segmentation 비교](/assets/img/ai_paper_reviews/R-CNN/r-cnn-fig1.png)

이 논문은 Object detection분야를 개척한 선구적인 논문임.
Object detection이란 이런식으로 사진내의 객체를 Bounding box로 표시하고, 분류까지 수행하는 작업임.
여담으로 다음주에 볼 segmantation은 bounding box가 아니라 픽셀수준으로 표시함

과거에는 객체탐지를 할때 canny edge detection, HOG같은 저수준 특징을 가지고 사람이 수작업으로 “저런 패턴이 5번 보이면 손이야” 하는 식의 feature engineering을 진행하고, 고수준 특징으로 변환하는 방식을 사용했으나, 시스템이 복잡하고 비효율적이며 발전이 정체되어있었음 (PASCAL VOC 데이터셋 기준)

그런데 딱 이 시기쯤이 복잡한 feature engineering 대신 End to End로 원본 데이터만 넣어주면 저수준부터 고수준까지 특징을 추출하고 분류하는 딥러닝으로의 패러다임 전환이 일어나는 시기였고, 이 논문도 딱 그 케이스임. 

1. 이 논문은 영상이 있으면 먼저 영역 제안(Region proposal)을 통해 객체가 있을만한 위치를 먼저 찾고, 해당 위치를 CNN을 통해 분류하는 방식을 제안함. 그래서 R-CNN이라고 불림
2. 또한, 데이터수가 적은 PASCAL VOC으로만 학습하는게 아니라, 대용량데이터로 사전학습하고 PASCAL VOC로 파인튜닝을 진행하는 방식도 제안했음.

지금 연구자들에게는 일반적인 특징을 먼저 학습하고 파인튜닝하면 좋아지는게 너무나도 당연하게 들리지만, 10년전 저 당시에는 정말로 큰 발견이었던것같음

## 1. Introduction

CNN은 사실 90년대에도 활발히 사용되다가, SVM에 밀려났다고 함.
그러나 시간이 지나고 ReLU를 통해 깊은 신경망의 기울기 소실을 해결해서 막혀있던 역전파가 해금되고, 많은 데이터가 생김과 동시에 Dropout을 통해 효과적인 학습이 가능해지면서 AlexNet을 시작으로 CNN이 부활함

그래서 이 논문의 저자들은 저 CNN을 이용해 이미지 분류를 해결함.
여기서, 부족한 타겟도메인 데이터에 비해 깊고 큰 CNN 모델을 사전학습→ 파인튜닝 방식으로 훈련해서 성공적으로 분류하는것도 큰 기여였음

또한 object detection은 분류만 하면 되는게 아니라 객체의 위치를 지정하는 localization를 먼저 해야하는데, 
우선 기존에 사용되는 방법론으로 해결되는지 보기위해 회귀방식의 접근법과 sliding window를 사용하는 방식을 먼저 시도해봤다고 함.

근데 회귀방식으로 사진을 주고 객체들의 위치를 뱉어내는 순수회귀방식은 별로 성능이 좋지 않았다고 함.

sliding window방식은 어땠냐?
원본 사진에서 스트라이드 1씩 모든 윈도우를 일일히 돌려보는방식은 계산량이 말도 안되는 비현실적 방법이라, feature map에서 sliding window를 사용해서 특징을 읽는 방식을 사용했는데, 여기같은 깊은 CNN에서는 pooling이 여러번 적용되어 feature map에서 한 스트라이드씩 움직여도 원본 사진에서 유효 스트라이드가 엄청 커짐.
그래서 원본이미지에서의 공간적인 해상도가 너무 떨어지는 문제가 생겨서 이것도 pass…

![R-CNN 파이프라인: 영역 제안, warp, CNN 특징 추출, 영역 분류](/assets/img/ai_paper_reviews/R-CNN/r-cnn-fig2.png)

**그럼 이 논문 저자들은 어떻게 localization 문제를 해결했냐?**

1. 먼저 Selective Search 라는 전통적인 알고리즘 기법을 사용해서 원본이미지에서 객체일 가능성이 높은 후보 영역들을 2000개 추려내고, 
2. 그 후보 영역들을 CNN과 SVM을 통과시켜 분류하는, 일종의 효율적인 원본이미지 슬라이딩 윈도우 방식(실제로는 슬라이딩 하진 않지만)을 사용함

## 2. Object detection with R-CNN

이 object detection system은 크게 3가지 모듈로 구성된다고 함
첫번째는 category-independent region proposals라는 모듈로, 객체의 종류에 상관없이 객체처럼 보이는 영역을 제안하는 역할을 한다고 함
두번째는 (227,227) 크기의 이미지를 받아 4096차원의 특징벡터를 출력하는 CNN 모듈
세번째는 4096차원의 특징벡터로 분류를 수행하는 SVM 모듈

### **2.1. Module design**

영역제안에는 objectness, selective search, CPMC등의 여러가지 방법들이 나와있는데, R-CNN은 다 쓸 수 있지만 저자들은 selective search를 선택함

![warp된 입력이 AlexNet 구조를 거쳐 4096차원 특징벡터가 되는 과정](/assets/img/ai_paper_reviews/R-CNN/r-cnn-fig3.png)

그리고 이 논문은 특이하게 CNN을 분류기가 아니라 특징추출만 하는 추출기로 사용했는데, 아키텍쳐는 5개의 컨볼루션 레이어와 2개의 완전연결 레이어로 구성되어있음. 
입력은 VGG에서도 봤듯이 zero-mean 정규화된 (227,227) 크기의 RGB이미지인데, 영역제안은 저 크기가 지켜지지 않고 그냥 아무사이즈로 추천하기 때문에 억지로 (227,227)크기로 변환하는 warping을 해주는데, 그 전에 원본 이미지에서 16픽셀만큼의 주변 정보를 패딩해서 맥락정보도 일부 추가해줌

테스트시에는 제안된 2000개의 영역들을 CNN 과 SVM을 거쳐 점수화하는데, 이때 SVM을 전통적인 방식대로 초평면 분류하는게 아니라 마진을 이용한 일종의 회귀를 한다고 함

영역들이 2000개나 되기때문에 한 객체에 대해서도 여러개의 bounding box가 생기는데, 우선 각 객체에 대해서 가장 점수가 높은 상자를 정하고, 얘랑 겹치는 애들(IoU값이 일정수준 이상이면)은 버려버림 
조금이라도 겹치면 다 버리면 되는거 아닌가 했는데, 객체들끼리 가까우면 박스가 실제로 겹치는경우가 많아서 그렇게 하는건 좀 위험함

또, 저자들은 런타임이 빠른이유가 자기들은 클래스별로 CNN이 따로있는게 아니라 한 CNN으로 모든 영역들을 다 돌리고, CNN 특징벡터도 다른 방법들에 비해 훨씬 저차원인 4k(4096)이라서 그렇다고 자랑하는데, 그럼 당연히 CNN하나로 다 하지 클래스별로 CNN을 쓰나? 너무 당연한거 아닌가? 싶어서 많이 당황했음…
근데 놀랍게도 SVM은 클래스별로 하나씩 가지고 있다고 함
10년정도밖에 안됐는데도 그동안 엄청나게 차이가 많이 벌어진듯

### **2.3. Training**

backbone CNN으로는 Alexnet을 사용했음 

사전학습에서는 풍부한 ILSVRC2012 데이터셋을 사용하고, 1000개 크기의 head 붙여서 분류

그 후, 파인튜닝할때는 head를 (N+1)크기의 head로 갈아끼워줌.
여기서 왜 N+1이지 했는데, 하나는 배경으로 아무 객체도 아닌걸 분류하기 위함이라고 함
VOC에서는 N=20, ILSVRC2013에서는 N=200인데, 둘다 bounding box가 주어지는 데이터셋임.
그냥 이미지 분류만 하던 ILSVRC2012과 달리 ILSVRC2013은 Object detection 대회인듯
또, 훈련할때 제안한걸 다 써주는게 아니라 IoU ≥ 0.5 을 넘는 샘플만 제대로된(양성)걸로 간주하고 훈련에 사용. 

SVM을 훈련시킬때는 Ground truth bounding box 하나만 정답으로, Ground truth bounding box와 IoU가 0.3 미만인 모든 이미지는 오답으로 설정함
0.3 이상인 이미지 처리가 되게 특이한데 얘들은 회색지대로 간주해서 사용하지 않았다고 함.
정답라벨에서 몇픽셀 이동해서 IoU가 0.95처럼 나오는 애들조차도…
0.3이라는 임계값은 validation셋으로 체크포인팅? 처럼 해서 최적인 값을 선택한거라고 함
