## 0. Abstract

LLaVA가 최초의 multimodal LLM 인줄 알았는데, 사실 LLaVA 이전에도 flamingo, BLIP-2, KOSMOS-1 등이 이미지 인코더를 LLM에 연결하는 방법을 사용하고 있었다고 함.
근데 LLaVA가 유명한 이유는, 기존에는 이미지를 보고 caption만 딱 뱉거나 단답만 했었는데 LLaVA는 제대로 된 assistant 형식의 자연어응답을 생성하는 최초의 멀티모달 챗봇이었기때문.

## 3. GPT-assisted visual instruction data generation

멀티모달 Assistant형태로 훈련을 하기위해서는 image + 사용자 instruction → assistant 답변 형태의 instruction following 데이터셋이 필요한데, 기존의 멀티모달 데이터셋들은 image + caption 형태의 원시적인 captioning task 맞춤 데이터들이 대부분이었음.

그래서 captioning task 맞춤데이터들을 instruction following 데이터셋으로 변환하기위해 GPT-4를 사용했는데, 이때 GPT-4는 4o가 아니라 진짜 언어모델링만 가능해서 이미지를 넣는대신 caption과 bounding box 정보를 넣어주고 데이터를 합성해내도록 함.

![instruction-following 데이터 예시: 캡션과 박스 정보를 주고 GPT로 대화·상세설명·복합추론 응답을 합성](/assets/img/ai_paper_reviews/LLaVA/llava-fig1.png)

합성되는 데이터는 위와같이 3종류임.

Conversation: 이미지에 대해 Q(사용자 instruction), A(assistant 응답) 데이터셋을 합성함.
multi turn이라고 하긴 하는데, 연속되는 느낌이라기보단 single turn 여러개가 붙은 형식만 multi turn느낌…

Detailed description: 이미지에 대한 자세한 설명(A)을 합성함.

Complex reasoning: 이미지에 대해 추론을 요구하는 Q, A 데이터셋을 합성함.

그래서 한 image에 대해 3가지 종류의 여러 turn 데이터가 합성됨.

## 4. Visual instruction tunning

![LLaVA 구조: Vision Encoder의 출력을 projection W로 변환해 언어 instruction과 함께 Language Model에 입력](/assets/img/ai_paper_reviews/LLaVA/llava-fig2.png)

Vicuna를 LLM backbone으로 사용하고, 이미지 인코더로는 CLIP의 이미지 인코더를 사용함.
이미지 인코더를 통과한 표현벡터 $$Z_v$$를 projection layer를 한번 통과시켜 $$H_v$$로 만들고, 이를 전통적으로 LLM의 input으로 들어가는 자연어 instruction 표현벡터 $$H_q$$와 concat 시켜 넣어줌.

![모델 학습에 쓰인 입력 시퀀스 형식: 시스템 메시지와 Human·Assistant 턴의 반복](/assets/img/ai_paper_reviews/LLaVA/llava-fig3.png)

그리고 훈련할때는 이미지의 각 turn을 가지고 훈련하는게 아니라, 이런식으로 특이하게 이미지에 대해 모든 turn을 다 합쳐서 input으로 넣어주게됨.
그래서 가령 imageB의 turn 6을 학습할때도 input으로 앞의 turn 1~5까지의 instruction과 golden응답(teacher forcing 때문에), turn6의 instruction이 input으로 들어가는 구조임.

$$
p(X_a \mid X_v, X_{instruct}) = \prod _{i=1}^L p_{\theta}(x_i \mid X_v, X_{instruct<i}, X_{a<i})
$$

따라서 loss에서 확률은 이렇게 계산됨.

훈련은 Stage1과 Stage2로 나누어서 진행함.
Stage1, 2 둘다 fine tuning 과정이지만, 저자들은 Stage1을 pre-training으로, Stage2를 fine-tuning으로 분류함.

**Stage1:** 
먼저 첫 스테이지에서는 이미지 인코더의 표현벡터를 LLM이 알아들을수 있도록 이미지 인코더와 LLM 백본은 fix 해두고 projection layer $$W$$만 학습시킴. 
이 단계에서는 아까 만든 합성데이터말고, CC3M이라는 image-caption 데이터셋을 아주 naive하게 저품질 instruction following 형태로 변형한 데이터셋을 사용함.
Stage2에서 projection layer 학습할건데 왜하는거지? 싶었는데, 약간 RL에서 cold start 하는 느낌인듯.

**Stage2:**
여기서는 이미지 인코더만 fix 해두고 LLM backbone $$\phi$$ 와 projection layer $$W$$를 학습시킴.
여기서 아까 합성해둔 고품질의 instruction following 데이터셋 사용.
