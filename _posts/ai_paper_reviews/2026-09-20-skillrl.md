## 0. Abstract

ALFWorld, WebShop, multihopQA같이 복잡한 상호작용을 하는 task에서 LLM 기반의 agent들이 좋은 성능을 보여줬음.
여기에 과거 경험으로부터 학습 할 수 있도록 raw trajectory로 메모리를 구축하려는 방법들이 있었음.
근데 raw trajectory에는 노이즈가 많아서 교훈을 도출하는데 방해가 크다는 문제가 있어서, 자기들은 SKILLRL이라는 방법을 통해 효과적으로 agent의 정책과 memory를 공진화시킨다고 함.

raw trajectory를 바로 참고자료로 갖다쓰는건 직관적이지만 노이즈가 많아서 모델이 핵심적인 정보를 추출하기어려움.
그래서 raw trajectory를 압축하고 메모리를 업데이트하려는 시도도 있었는데, 압축은 지식을 깨닫는 고차원적인 과정이 아니라 단순하고 기계적인 과정이서 별로라고 주장함.
그리고 저자들은 효과적인 학습을 위해서는 경험의 추상화가 필수적이라고 함.
아마 추상화가 정보에서 핵심적이고 보편적인 부분을 찾아 일반화를 가능하게해주고, 의사결정을 방해하는 노이즈를 빼고 알짜만 증류하는 과정이라서 그렇게 생각하는것같고, 타당한듯.

자기들은 그래서 경험은 demonstration으로, 실패한 에피소드는 노이즈를 줄이기 위해 간결한 실패 교훈으로 요약하고, 이렇게 변환된 Skill을 SkillBank에 넣는데, SkillBank도 보편적인 상황에 사용되는 일반스킬과 과제수준의 휴리스틱인 과제특화스킬로 나뉨.

## 2. Preliminaries

task $$d$$, skill $$c$$ 가 주어졌을때, 수익을 최대화하도록 정책 $$\pi_\theta(a_t \mid o_{\leq t},d,c)$$ 를 최적화하는것이 목표.
일반적인 LLM에서의 RL과 달리 skill $$c$$ 까지 조건부에 들어가있음.
그리고 RL 알고리즘으로는 GRPO를 사용한다고 함.

## 3. SkillRL

![논문 Figure 2: SkillRL 프레임워크 개요 - base model로 trajectory 수집, 계층적 skill library로 증류, cold-start SFT, validation 실패 기반의 skill 진화와 함께하는 RL 학습](/assets/img/ai_paper_reviews/SkillRL/skillrl-fig2.png)

SKillRL의 핵심을 3가지로 요약함.
1. 중복과 노이즈가 많은 trajectory를 skill로 추상화하는 증류 메커니즘
2. 일반 skill과 과제특화 skill로 분류된 계층적 라이브러리 SkillBank
3. RL을 활용해 agent의 정책과 skill을 같이 최적화해나가는 재귀적 진화 메커니즘

### 3.1 Experience-based skill distillation

![논문 Table 5: ALFWorld용 SkillBank에서 증류된 skill 예시 (ID, Skill Title, Principle, When to Apply)](/assets/img/ai_paper_reviews/SkillRL/skillrl-fig3.png)

![논문 Table 6: ALFWorld에서 흔한 에이전트 실패 유형과 완화 전략](/assets/img/ai_paper_reviews/SkillRL/skillrl-fig4.png)

훈련되지않은 basemodel이 출력한 원시 trajectory $$\tau$$가 있다고 할때, 성공케이스와 실패케이스 모두 o3같은 teacher model에 task description $$d$$ 와 함께 집어넣음

$$s^+=\mathcal{M}_T(\tau^+,d)$$는 작업을 성공으로 이끈 원칙을, $$s^-=\mathcal{M}_T(\tau^-,d)$$는 실패분석을 위주로 추출.

### 3.2 Hierarchical skill library construction

SkillBank는 $$\mathcal{S}_g , \mathcal{S}_k$$ 로 구성되며, $$\mathcal{S}_g$$는 항상 포함되고, 특화 skill $$\mathcal{S}_k$$만 그때그때 검색함.

$$
 \mathcal{S}_{ret}=\text{TopK}(\{s \in \mathcal{S:\text{sim}(e_d,e_s)>\delta}\},K)
$$

skill을 검색해올때는 그냥 task의 임베딩 $$e_d$$, skill의 임베딩 $$e_s$$으로 유사도검색하고 TopK 한다고 함.
이후 skill을 정책모델에 입력해주고, $$a_t \sim \pi_\theta(a_t \mid o_{\leq t},d,\mathcal{S}_g,\mathcal{S}_{ret})$$ 행동은 이렇게 샘플링

### 3.3 Recursive skill evolution

<figure style="width:61%; margin:0 auto;">
  <img src="/assets/img/ai_paper_reviews/SkillRL/skillrl-fig5.png" alt="논문 Algorithm 1: SkillRL 의사코드 - 경험 기반 skill 증류, 계층적 skill library 구축, RL을 통한 재귀적 skill 진화" style="width:100%;">
</figure>

**Cold start initialization**
먼저, 본격적인 RL에 들어가기 전에 cold-start 문제를 해결하기위해 SFT로 skil을 효과적으로 활용하는방법을 학습시킴.
이때 필요한 데이터셋 $$\mathcal{D}_{\text{SFT}}=\{(d_i,\mathcal{S}_i,\tau_i^*)\}$$은 teacher model $$\mathcal{M}_T$$로 생성.

**Recursive skill evolution**
SkillBank 진화도 전적으로 teacher model $$\mathcal{M}_T$$에 의존하는데, 먼저 주기적으로 validation set에서 하위 작업카테고리 $$C$$ 별 성능을 측정함.
이후 정확도가 threshold $$\delta$$ 미만인 카테고리는 휴리스틱한 기준에 의해 실패궤적 $$\tau^-_{val}$$을 수집하고, 이걸 $$\mathcal{M}_T(\tau_{val}^-,\text{SKILLBANK})$$ 이렇게 teacher model에 넣어서 기존 skill을 업그레이드하거나 새로운 skill을 생성하도록 함.

**RL-based policy optimization**
GRPO로 정책 학습하는데, 보상으로는 PRM이 아니라 ORM을 사용한다는 이야기.

- 기존 문제:<br>
agent에서 경험을 재사용할때, 나이브하게 raw trajectory를 써왔는데 노이즈가 많아서 문제가 있었음.
- 핵심 아이디어:<br>
경험을 자연어로 추상화해서 skill로 증류하고, 이걸 모델이 잘 사용하도록 RL.<br>
또한, skill도 outdated 되지않게 co-evolution.
- 왜 좋아졌는지:<br>
RL덕분인것같음.<br>
대신 skill을 쓰도록 RL을 하려면 skill형태로 raw trajectory를 추상화해줘야함.
- 데이터/메트릭/베이스라인:<br>
ALFWorld랑 WebShop등을 벤치마크로 사용했고, 베이스라인으로는 메모리 기반 agent들이랑 RL로 훈련한 agent들 사용.
- 실험설계에서 문제점:<br>
딱히 없는것같지만 자세히 보지는 못함… 이쪽을 아직 거의 몰라서
- 한계 한 줄:<br>
skill을 가져오는 방식이 너무 나이브하고, SkillBank를 co-evolution하는 방식을 전적으로 외부의 teacher model에 의존한다는게 치명적
