## 0. Abstract

LLM agent들은 기억이 파라미터에 묶여있기때문에 학습된 후에는 추론과정을 진행한다고 추가적인 지식이 저장되지 않음.
즉, RL로 치면 행위의 주체인 agent가 직접 상호작용을 하지 않는 Offline RL방법임.
근데 agentic 작업들은 학습된 파라미터뿐만 아니라 이전에 시도한 경험들을 기억하고 참고해야 수월하게 진행될수 있는 경우가 많아, 이런 경험들을 기억하고 효과적으로 사용할수 있도록하는 방법론인 $$Mem^p$$를 제시함.
이렇게하면 Online RL처럼 배포후에도 환경과 상호작용하며 꾸준히 학습할수 있음.

## **1. Introduction**

![논문 Figure 1: procedural memory가 없으면 시행착오로 느리고 부정확하지만, 있으면 비슷한 task에서 정확도는 오르고 스텝 수는 줄어듦](/assets/img/ai_paper_reviews/Mem-p/mem-p-fig1.png)

LLM의 성능이 강력해짐에따라 LLM기반 agent들로 점점 복잡하고 어려운 과제들을 수행해나가고 있는데, 이런 과제는 수십번의 단계와 긴 실행시간이 필요함.
근데 보통 UI가 변경된다던지 데이터스키마가 바뀐다던지 환경이 동적으로 변하는경우가 많아 agile하게 경험으로부터 배우는 방식이 매우 중요함.
기존에는 agent 작업의 경험으로 부터 배우는 절차적 기억을 단순히 저장만 해주경우가 많았는데, 자기들은 메모리 구축, 검색, 업데이트등 종합적으로 절차적기억을 최적화하는 방법론이라고 차별점을 어필함.

## 4. Experiments

![논문 Figure 2: procedural memory 프레임워크 - Build(과거 trajectory를 Key-Value 메모리로 저장), Retrieve(새 task에 관련 메모리 검색), Update(추가·수정·삭제)](/assets/img/ai_paper_reviews/Mem-p/mem-p-fig2.png)

Query, Key, Value로 구성
Query는 현재 agent가 수행해야하는 작업지시사항 , Key는 과거 기억을 찾기위한 일종의 라벨, Value는 과거기억 내용임

### 4.1 Experimental Settings

벤치마크와 데이터셋으로는 TravelPlanner와 ALFWorld 를 사용함.

백본으로 사용한 모델은 GPT-4o, Claude, Qwen2.5-72B-Instruct 임.

### 4.2 Memory Storage & Retrieval

![논문 Table 1: Build Policy 결과 - No Memory, Script, Trajectory, Proceduralization 방식별 TravelPlanner와 ALFWorld 성능](/assets/img/ai_paper_reviews/Mem-p/mem-p-fig3.png)

Value를 구현하는데 여러 선택지가 있는데, 성공했던 과거의 경로를 그대로 사용하는 Trajectory 방식, 과정을 요약해서 추상화된 지침을 만들어놓은 Script 방식, 로그와 요약본을 합쳐놓은 Proceduralization 방식이 있음.
비교해보니 Memory를 안쓰는 방식에 비해서 세 방법이 모두 점수와 필요한 스텝수 측면에서 좋았고, 그중에서 전반적으로 Proceduralization방식이 가장 성능이 좋은듯함.

Key는 과거 기억을 찾기위한 일종의 라벨인데, 과거작업의 Query를 그대로 사용하는 Query방식과 핵심 키워드들만 뽑아 그 벡터들의 평균값을 사용하는 AveFact방식이 있음.

### **4.3 Memory Update**

![논문 Figure 3: trajectory 그룹이 진행됨에 따른 Vanilla, Validation, Adjustment 업데이트 방식의 보상 향상과 스텝 감소](/assets/img/ai_paper_reviews/Mem-p/mem-p-fig5.png)

메모리에 경험들을 업데이트할때도, 여러가지 선택지들이 있음.
기본적으로 과제를 수행하고 맞았는지 여부에 상관없이 모든 trajectory들을 메모리에 추가하는 Vanilla 방법, 성공한 과제만 trajectory를 메모리에 추가하는 Validation 방법, 실패한 trajectory의 경우 reflection기법등으로 수정해서 메모리에 추가하는 Adjustment 방법이 있음.

위의 그래프에서, 메모리를 사용하지 않았을때 대비 성능향상을 보면, Adjustment방법이 가장 효과적인것을 알 수 있음.
