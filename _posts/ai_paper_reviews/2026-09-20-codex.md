## 0. Abstract

GPT-3 12B 모델을 Github 코드로 fine-tuning했고, 이 모델을 Codex라고 부름.
Github Copilot은 이 Codex를 엔진으로 사용한다고 함! 
코드가 실제로 기능하는지 테스트하기위해 HumanEval이라는 벤치마크를 만들었는데, 그 결과 GPT-3는 0%, 즉 거의 아무것도 못풀었지만 Codex는 28.8%이 나왔다고 함
그리고 Best-of-N 방법을 통해 100개의 샘플을 만들게하면 점수가 70.2%까지 치솟았다고 함.

## 1. Introduction

당시 언어모델이 급격하게 발전하고 있는 시기였고, GPT-3가 docstring을 주면 간단한 프로그램을 짤 수 있는걸 보고 코드 생성에 대한 잠재력을 발견함.
그래서 코딩에 특화된 모델을 만들어보자는 동기부여가 생겼고, 기존의 평가방식은 출력한 문장이 얼마나 정답과 비슷한지 측정하는 BLEU같은걸 주로 사용했기때문에 기능적 정확성을 기준으로 하는 HumanEval이라는 164개의 문제세트를 제작함.

그걸로 측정해보니까, 앞서 말했던것처럼 GPT-3는 0%에 가까운 점수가 나왔고, GPT-J는 11%정도였지만 Codex는 28.8%라는 엄청난 성능차이를 보였다고 함.
심지어 제대로 코드를 구현한 데이터로 훈련한 Codex-S는 37.7%가 나옴.
GPT-J는 코드가 섞여있는 The Pile 데이터셋으로 pre-trained된 6B크기의 베이스모델임.

Inference time scaling을 통해 샘플을 여러개 생성하는 방식을 사용하면 정답을 알고있는 Oracle Reranking에서는 Codex-S기준 77.5%, 실질적으로 쓸수있는 방법인 log p 방식은 44.5%의 성능을 보였다고 함.

## 2. Evaluation Framework

### 2.1. Functional Correctness

$$
\text{pass}@k := \mathbb{E}_{\text{Problems}} \bigg[ 1- \frac{\binom{n-c}{k}}{\binom{n}{k}}\bigg]
$$

매번 생성하는건 비용이 많이 드니까 미리 $$n$$개의 답변을 생성하고, 거기서 $$k$$개를 뽑는식의 불편추정량을 사용함.
$$c$$는 $$n$$개의 답변중에서 정답을 맞춘 샘플들의 수임.

### 2.2. HumanEval: Hand-Written Evaluation Set

164개의 간단한 프로그래밍문제를 직접 만들었고, 평균 7.7개의 테스트케이스로 구성되어있다고 함.

### 2.3. Sandbox for Executing Generated Programs

채점을하려면 결국 코드를 실행해봐야하는데, AI가 Github을 학습했기때문에 예기치못하게 악의적 코드를 작성할수 있어서 gVisor이라는 격리된 환경을 생성하고 거기서 코드를 돌림.

## 4. Supervised Fine-Tuning

근데 Codex는 Github에서 코드라면 그냥 긁어서 훈련한거라 쓸데없는 비중이 높을거라고 추측했고, 그래서 알고리즘 사이트와 CI가 되고있는 프로젝트에서 진짜 알짜 데이터셋을 가지고 Supervised fine-tuning을 진행해서 Codex-S를 만듦.
CI는 코드가 수정될때마다 자동으로 테스트를 돌린다고 하는데, 이때 어떤 함수가 실행되고 어떤 값이 나오는지 기록되어서 문제를 만들기 쉽다고 함.

### 4.1. Problems from Competitive Programming

알고리즘사이트에서 10000문제를 확보했다는 이야기

### 4.2. Problems from Continuous Integration

sys.setprofile을 켜놓고 자동으로 함수를 추적해서 40000개의 문제를 확보함

### 4.3. Filtering Problems

이상하거나 너무 어려운 문제도 수집될 수 있어서, Codex-12B를 써서 100번을 풀게했는데도 못하면 문제 제외함

## 5. Docstring Generation

Codex와 Codex-S는 docstring을 보고 코드를 짜는 모델이었다면, 반대로 코드를 보고 docstring을 짜는 모델도 필요함. 
그래서 이번엔 Codex-S를 만들때와는 반대로 코드를 보여주고 docstring을 예상하게 supervised fine-tuning을 했고, 이렇게 만들어진게 Codex-D임.
이 모델을 평가할때는 자동으로 할수있는방법이 없어서 연구원들이 직접 보면서 채점했다고 함.
