## 0. Abstract

기존에는 질의응답, 요약, 번역 등 다양한 자연어 task에서 정답데이터가 필요했었음.
그런데 이 논문에서는 WebText라는 데이터셋으로 사이즈가 큰 모델을 pre-training시켰더니 지도학습 없이도 Zero-shot(여기서의 Zero-shot은 모델의 가중치를 전혀 수정 안한다는 뜻)설정으로 SOTA를 찍어버렸다고 함.
즉, fine-tuning을 할 필요가 없어진거임

---

## 1. Introduction

지도학습이 좁은영역의 전문가모델 훈련에는 괜찮아도 범용적인 작업에는 그다지 좋지 못하다고 지적함.
범용적인 제너럴리스트 모델을 만들려면 단일 도메인 데이터셋이 아니라 다양한 도메인과 task를 훈련해야되는데, 지금처럼 지도학습에 필요한 데이터셋을 직접 만들고 목적함수도 짜는방식은 scalable하지 않다고 함.
당시 SOTA를 찍던 pre-training 후 fine-tuning 방법도 언급하는데, 어쨌든 이것도 fine-tuning을 하는 방법이라고 짚음.
그래서 자기들은, 더 일반적인 모델 학습을 위해 지도학습 없이도 Zero-shot으로 downstream task를 수행하는것을 보였다고 함.

## 2. Approach

<figure style="width:56%; margin:0 auto;">
  <img src="/assets/img/ai_paper_reviews/GPT-2/gpt-2-fig1.png" alt="논문 Table 1: WebText 학습 데이터에 자연스럽게 등장하는 영어-프랑스어 번역 demonstration 예시" style="width:100%;">
</figure>

언어모델링 관점에서 단일작업 학습은 $$p(output\mid input )$$을 배우는것임.
제너럴리스트모델은 다중작업에서도 작동해야하므로 $$p(output \mid input, task)$$를 배우는것으로 이해할 수 있는데, 사실 $$task$$도 $$input$$을 보고 추론할 수 있는것이므로, 모델의 capacity만 충분하면 자연어 시퀀스에 포함된 task demonstration을 보면서 task를 추론하기 시작할것이라는 가설을 세움.

### 2.1. Training Dataset

기존 연구들은 보통 언어모델을 하나의 도메인에서만 훈련한것으로 판단했음.
그래서 자기들은 가급적 크고 다양한 데이터셋을 구축하기위해 Common Crawl같은 웹 스크래핑 데이터를 사용하려고 하는데, 저건 너무 품질이 낮아서 쓸수가 없었다고 함.
그래서 대신 레딧에서 karma(별같은거) 3개 이상 받은 링크를 크롤링하는방식을 사용했다고 함.
레딧이 지식인같은건줄 알았는데, 링크갖고와서 공유하고 이야기하는 커뮤니티라고 함.
그렇게 완성된게 800만개의 문서를 가진 40GB용량의 WebText임.
2017년 12월 이전의 문서만 있고, 위키피디아는 test셋 contamination 우려로 제외함.

GPT-1의 BookCrawl은 그럼 어땠는지 물어봤는데, 크지도 않고 task도 다양하지 않은 데이터셋이었다고 함.

### 2.2. Input Representation

토크나이저도 바꿨는데, GPT-1에서는 글짜 단위의 BPE였다면, 여기선 byte 단위의 BPE임.
글짜단위 BPE는 세상 모든 글짜를 표현하려면 기본어휘집합이 너무 커졌음.
근데 UTF-8기준 바이트단위는 256개가 기본어휘이므로 괜찮음.
그리고, dog. dog? dog! 을 별도의 vacab으로 인식하는 비효율을 막기 위해 문자종류가 다른건 못합치게 함.

### 2.3. Model

모델 아키텍쳐는 GPT-1과 거의 동일하지만, layer norm 위치를 바꾸고 window(context)는 1024로 늘리는등의 몇몇 수정이 있었음.

## 3. Experiments

로그스케일에서 균등한 간격이 되도록 크기를 조절한 모델 4개를 만듦.
첫번째는 GPT-1과 동일한 크기, 두번째는 $$\mathrm{BERT_{large}}$$와 동일한 크기이고, 마지막은 GPT-1의 10배가 넘는 크기로 GPT-2라고 부름.

### 3.1. Language Modeling

![논문 Table 3: 여러 언어모델링 데이터셋에서의 zero-shot 결과와 기존 SOTA 비교](/assets/img/ai_paper_reviews/GPT-2/gpt-2-fig3.png)

GLUE나 SQuAD같이 직접적으로 AI를 써먹으려는 Downstream task 벤치마크가 아니라 Language Modeling하는곳, 즉 기초지식을 배우는 Upstream task 벤치마크로 성능측정함.
성능측정할땐 PPL(Perplexity)를 주로 사용하고, 사촌격인 BPB/BPC나 정확도 ACC도 많이 씀.

근데 이런 언어모델링 벤치마크는 대부분 자연어형태가 아니라 토큰화되고 변형된경우가 많아서, De-tokenizer를 이용해 원래 자연어형태로 바꿔주면 PPL이 2.5~5점정도 나아졌다고 함.
결과적으로, Upstream 벤치마크 8개 중 7개에서 SOTA를 찍음.

### 3.2. Children’s Book Test

<figure style="width:80%; margin:0 auto;">
  <img src="/assets/img/ai_paper_reviews/GPT-2/gpt-2-fig4.png" alt="논문 Figure 2: 모델 크기에 따른 Children's Book Test 정확도 (Common Nouns, Named Entities)" style="width:100%;">
</figure>

동화책 문장에서 단어 하나를 지우고 10개의 보기 선지 중 정답을 고르는 문제임.
모델이 후보를 넣어보고 확률이 높게 나오는 애를 고르는 Scoring 방식으로 채점.
품사별로 성능을 측정하는데, 모델 크기가 커질수록 인간성능과 격차가 줄어들었고, 결국 인간수준에 근접함.
CBT라고 줄여서 부름.

### 3.3. LAMBADA

이 벤치마크는 언어모델이 긴 문맥에서 장기의존성을 얼마나 잘 처리하는지 평가함.
문장에서 마지막 단어를 예측하는건데, 최소 50토큰 이상의 문맥은 봐야 맞출수있는 문제임.
기존 SOTA Perplexity가 99.8이었는데, GPT-2는 8.6까지 떨어뜨리는 미친 성능을 보여줌.
정확도도 기존 SOTA는 19%였는데, GPT-2는 52.66%까지 찍음.
이것도 Scoring방식으로 채점

### 3.4. Winograd Schema Challenge

이 벤치마크는 상칙추론능력을 평가하기 위해 모호한 문장을 해결해보도록 함.
예를들어 "트로피가 가방에 들어가지 않는다. 왜냐하면 그것이 너무 크기 때문이다."  에서 “그것”이 무엇인지 맞춰보도록 하는것임. 이것도 Scoring방식으로 채점
여기서도 GPT-2가 70.7%의 정확도로 기존의 SOTA를 7%차이로 눌러버림

### 3.5. Reading Comprehension

CoQA라는 지문을 읽고 대답해야하는 벤치마크에서도 실험함. 일반적인 비문학지문급으로 어렵다고 함.
당연히 fine-tuning도, few-shot도 없는 zero-shot으로 실험했는데 지도학습한 baseline 4개중에서 3개를 상회하는 엄청난 성능이 나왔다고 함.
보기가 없고 모델이 다음단어나 문장을 직접 생성하는 Generation방식임. 이후의 모든 task도 Generation방식.

### 3.6. Summarization

![요약 task 예시: 기사 원문과 GPT-2가 생성한 요약, Reference 요약 비교](/assets/img/ai_paper_reviews/GPT-2/gpt-2-fig5.png)

TL;DR: 이라는 자연어 프롬프트를 붙여보니 요약 비스무리한 행동을 했음.
겉보기에는 그럴듯한 진짜 요약문처럼 생겼으나, 실제로 자세히 봤을땐 점수가 처참했다고 함.
그러나, 자연어를 통해 task에 맞는 응답을 출력할수 있는 가능성을 발견했다고 함

### 3.7. Translation

```
english sentence = french sentence
English sentence = 
```

이런식의 프롬프트를 통해 프랑스어랑 영어 사이의 번역을 하게 만들었음.
영어 → 프랑스어 성능은 폭망이었는데, 프랑스어 → 영어 성능은 상당히 좋았다고 함.
영어를 제외한 언어는 필터링했는데, 거기서 살아남은 10MB정도의 정말 작은 프랑스어만 보고도 번역을 배운거임

### 3.8. Question Answering

![논문 Table 5: Natural Questions에서 GPT-2가 가장 확신한 답변 30개의 정답 여부와 확률](/assets/img/ai_paper_reviews/GPT-2/gpt-2-fig6.png)

이건 지문을 읽고 대답하고 이런게 아니라 pre-training하고나서 모델 파라미터에 정보를 얼마나 내장했는지, 그냥 클로즈북으로 암기한걸 테스트하는 벤치마크임.
성능은 SOTA에 비해 많이 낮았지만, 자기가 뭘 알고 뭘 모르는지 메타인지능력은 좋아서 위의 표의 예시처럼 자신있다고 한거에서는 되게 잘 풀었고, 모델이 커질수록 성능이 스케일링되는것도 확인할 수 있었음

혹시 pre-train 데이터셋이 contaminated 되었는지 확인해봤는데, WebText는 1~6%정도 겹쳤지만 별 문제는 없었고 오히려 기존 데이터셋이 더 많이 겹쳤다고 함.
그리고 학습곡선을 보면 오히려 데이터를 외워서 과적합되기는 커녕 한참 과소적합되어있어서 주어진 데이터를 완전히 소화하지도 못했다는것을 볼 수 있음.
가로축이 epoch인게 과대적합 그래프 아닌가? 했는데, 생각해보니 model size가 가로축이어도 똑같은 개형.

## 5. Related Work

자기들의 연구가 세가지 흐름을 계승한것으로 설명함.

첫째는 스케일링 법칙으로, 2020년의 스케일링법칙 이전에도 모델크기가 성능을 올려준다는것은 알려져있었음.
자기들은 그 경향이 1B 이상의 거대모델에서도 유효하다는것을 확인함.

둘째는 pre-training인데, Word2Vec에서 시작해 BERT까지 어려운 생성작업에서도 pre-training이 효과적이라는것을 확인했고, 자기들의 GPT-2도 그 흐름의 계승자라고 이야기함.

셋째로는 비지도 mulit task 연구흐름임.
Liu et al.(2018)의 연구에서 위키백과를 생성하도록 모델을 훈련했는데, 이름을 다른 언어로 번역하는 능력도 터득한 사례가 있어 데이터가 충분히 많다면 여러 task를 저절로 배우겠구나 하는 영감을 받았다고 함

## 6. Discussion

이전엔 많은 연구가 unsupervised pre-training에서 나온 표현을 적응시키고 써먹는데 집중했는데, 자기들은 그런 작업없이 그냥 pre-training만으로도 바로 다양한 task를 수행할수 있는걸 입증함.
심지어 이건 그냥 pre-training만 한거고 fine-tuning까지 했을때 성능이 어디까지 올라갈진 모른다고 함.

다만, 다양한 task에서도 독해는 GPT-2의 성능이 상당했으나 나머지 요약등의 나머지 task에서는 초보적인 수준이었고, 잘된것도 사실 모델 크기가 충분했을때였던 경우가 많았다는 점을 인정함

---

## 7. Conclusion

충분히 큰 모델을 충분히 크고 다양한 데이터셋으로 훈련시키면 지도학습 기반의 fine-tuning없이도 Zero-shot으로도 다양한 task에서 좋은 성능을 보이기 시작한다는 점을 강조.

**느낀점**<br>
Language Models are Unsupervised Multitask Learners 이라는 제목에서도 알수 있듯 이 논문에서의 가장 중요한 발견은 pre-training 단계에서 크고 다양한 데이터셋으로 학습시키면 fine-tuning으로 task별로 학습시킬 필요없이 바로 다양한 task를 수행할수 있는 Zero-shot 능력을 가지게 된다는것임.<br>
또한, 단순히 TL;DR 같은 자연어 입력을 붙이는것만으로 특정 task를 하도록 유도할수 있다는 점도 발견함.<br>
GPT-1이 생성적 비지도학습, 즉 pre-train을 하고 fine-tuning을 하면 좋다라는점을 발견했고 traversal style로 head 구조의 통일은 이뤘지만, 다시 판별적 모델로 써먹기 위해 여전히 task별로 head를 훈련해야했다면 여기서는 head 자체가 없음. 생성적 모델로 남고, 그냥 모델 본체만 있으면 됨.<br>
그 본체만 가지고 scoring이나 generation 방식으로 task 형식에 구애받지않고 수행가능함.
