# 0. Abstract

GPT-2같은 pre-training만 하는 방법론이 나왔음에도, 성능면에서 당시의 대세는 RoBERTa, T5같은 pre-training + fine-tuning 모델들이었다고 함.
근데 인간은 몇개의 예시나 간단한 지시만으로도 새로운 task를 수행할수 있는데, 모델도 궁극적으론 그렇게 되어야하지 않아? 하는 생각을 했음. 
그래서 GPT-3라는 175B의 거대한 언어모델을 만들어봤는데, 그랬더니 few-shot만으로도 다양한 task를 수행하고 generation 까지 훌륭히 해내는 범용모델이 된다는것을 발견함.

# 1. Introduction

fine-tuning은 기본적으로 task마다 수천 수만개의 라벨링 데이터가 필요한데, 무한히 많은 task의 종류 상 이건 불가능에 가까움.
또한, 그렇게 학습되면 OOD에서 성능이 떨어지는 약점도 있고, 무엇보다 인간은 새로운 작업도 간단한 지시나 예시 몇가지로 만 보고 실행할수 있음.

![논문 Figure 1.1: 언어모델 메타러닝 - pre-training의 outer loop와 시퀀스 안에서 일어나는 in-context learning의 inner loop](/assets/img/ai_paper_reviews/GPT-3/gpt-3-fig1.png)

이 문제를 해결하기 위해, GPT-2 에서 발견된 자연어로 task에 적응시키는 In-context learning을 도입함.
물론 GPT-2에서는 그렇게 하면 당시 SOTA였던 fine-tuning 기반 모델보다 성능이 형편없었으나, scaling을 하면 성능을 따라잡을 수 있을것이라는 가설을 세움.

이렇게 여러가지 크기의 모델들에 대해 여러 예시를 먼저 context에 넣어주는 Few-shot부터 그냥 작업지시만 있는 Zero-shot까지 실험해봄.
그랬더니 작은 모델은 여러 shot(예시)를 줘도 성능이 안오르지만, 거대모델은 shot이 늘어날수록 성능이 가파르게 상승하는모습을 보임
GPT-2 논문에서는 fine-tuning 안하고 가중치 안바꾸는걸 Zero-shot이라고 했는데, 여기서부터는 그건 In-context learning으로 묶이고 shot이 예시 개수로 쓰임.

## 2.1 Model and Architectures

![논문 Table 2.1: 8가지 GPT-3 모델의 크기, 아키텍처, 학습 하이퍼파라미터](/assets/img/ai_paper_reviews/GPT-3/gpt-3-fig5.png)

GPT-3도 여러 크기의 모델을 훈련함.
여기서, $$n_{heads}$$는 multi head attention에서 attention head의 개수, $$d_{head}$$는 attention head의 차원임.
 $$d_{model}$$은 MLP의 입출력 레이어의 차원, 안적혀있지만 MLP의 hidden의 차원은 $$d_{ff}=4\times d_{model}$$
모든 모델은 $$n_{ctx}=2048$$ 즉, 2048토큰의 컨텍스트 윈도우 사용.
가장 큰 모델인 GPT-3 175B, 즉 GPT-3는 크기가 175B고 Transformer 블럭이 96개임

## 2.2 Training Dataset

GPT-2에선 Reddit 링크를 필터링한 WebText만 썼지만, GPT-3는 데이터가 훨씬 더 필요해서 다시 Common Crawl에도 손을 댐.
데이터셋을 만들어낼때, 쓰레기 데이터를 걸러내기 위해 고품질데이터를 필터링하고, 중복과 test contamination 데이터를 제거하고, 고품질데이터가 더 필요해서 WebText2,Wikipedia같은 고품질데이터를 추가로 섞는 3단계 과정을 거침.

![논문 Table 2.2: GPT-3 학습에 쓰인 데이터셋별 토큰 수와 샘플링 비중](/assets/img/ai_paper_reviews/GPT-3/gpt-3-fig6.png)

훈련할때는, 표에 나와있듯이 데이터셋에서 그냥 샘플링하는게 아니라 고품질 데이터일수록 더 자주 샘플링되도록했다고 함.
전체 용량은 논문에 나와있지않지만, 대략 700GB정도일것으로 추축됨

## 2.3 Training Process

모델이 너무 커서 학습할때 V100 GPU에서 병렬화했고, 모델이 클수록 배치사이즈 키우는게 효율적이라 175B 짜리는 batch_size= 3.2M 토큰이었다고 함.

## 2.4 Evaluation

Few-shot 환경에서는 최적의 K개를 넣어주는데, 최대한 많을수록 좋은경우가 많아 보통 2048토큰 다 찰때까지 shot을 여러개 꽉 채워주는듯.

객관식을 채점할때는 전통적인 방법처럼 scoring방식으로 선지 개수만큼 [지문]+[질문]+[보기] 를 만들어서 모델이 어떤 선택지가 토큰의 평균 likelihood가 높은지 봄.
이진분류형 문제도 선지가 2개인 객관식처럼 평가함.
모델한테 직접 자연어로 “1번이요” 이런식으로 시키면 “paris”, “정답은 파리입니다”, 2번이요” 이런식으로 뒤죽박죽이라 저런식으로 안정적으로 채점하는듯.

질의응답이나 요약같은 주관식문제는 Beam search를 이용해 문장을 만들고 정답과 비교해서 F1이나 BLEU점수를 매긴다고 함.
사실 이방식도 GPT-2에서 있었던 방법이었음.

## 3.1 Language Modeling, Cloze, and Completion Tasks

![논문 Table 3.2: cloze 및 completion task(LAMBADA, StoryCloze, HellaSwag) 성능](/assets/img/ai_paper_reviews/GPT-3/gpt-3-fig8.png)

여기서는 언어모델링과 빈칸채우기(cloze), 문장완성 task에서의 성능 측정함.
우선 언어모델은 문장을 주고, 주루룩 문장 생성할때 perplexity를 측정하는데 PTB라는 데이터셋에서 Zero-shot으로 (전통 LM task라 Few-shot은 안씀)측정했을때 기존 SOTA보다 15점 낮은 20.5점을 기록하며 압도해버림. 
한 토큰 틀리면 뒤도 계속 주르륵 틀리는거 아니야? 했는데 이런 Language modeling은 틀려도 정답주고 다음 토큰 Perplexity 예측하게하는식으로 진행한다고 함.

빈칸채우기는 장기문맥인 LAMBADA에서 시험했는데, Zero-shot 으로도 76%를 찍으며 SOTA를 찍었고, Few-shot을 하니까 86.4% 까지 올라버림

문장 완성은 HellaSwag와 StoryCloze라는 이야기의 결말을 고르는 객관식문제를 풀게시켰는데, Few-shot 기준 SOTA를 이기진 못했지만 거의 그에 준하는 성능을 보여줌.

## 3.2 Closed Book Question Answering

![논문 Table 3.3: Open-Domain QA 3종(NaturalQS, WebQS, TriviaQA) 결과](/assets/img/ai_paper_reviews/GPT-3/gpt-3-fig9.png)

여기서는 GPT-3가 파라미터안에 지식을 얼마나 많이 저장하고있는지 평가함.
GPT-3는 검색이나 fine-tuning도 없는 완전 Closed book 조건인데도 TriviaQA에서는 외부 문서를 검색하는 당시 SOTA를 이겨버림.

NaturalQS와 WebQS에서는 성능이 TriviaQA에서 보여준 포스보다는 좀 덜한데, Zero-shot성능이 낮은게 GPT-3의 pre-train 데이터셋에서 OOD여서 그럴거라고 함.
근데 shot을 넣어주면 성능이 확 오르는게 금방 적응해서 성능을 회복하는거라고 분석.

그래도 여전히 전반적으로 상당히 쓸만한 성능을 보여줌.

### 3.9.4 News Article Generation

GPT-2에서도 유니콘 기사를 만들어내는 실험을 진행했었는데, 이번엔 GPT-3가 생성적으로 만들어낸 뉴스기사가 얼마나 진짜같은지 테스트함.
GPT-2가 pre-train할때 쓴 corpus에 비해 GPT-3할때 쓴 corpus에서는 뉴스기사가 별로 없어서 아무 조건없이 샘플링하면 트윗을 자꾸 이어서 썼다고 함.
그래서 few-shot을 통해 예시를 주니까 잘 만들어냈음.
