## 0. Abstract

지금까지는 다들 범용 에이전트를 만들기 위해 파운데이션 모델을 수작업으로 변형하는 접근법을 취했는데, 기계학습의 역사를 봤을때 이 에이전트를 만드는것 또한 수작업 엔지니어링 대신 자동으로 학습되는 방향으로 바꿔야한다고 주장함.
그래서 자기들은 에이전트 시스템을 자동으로 설계하는 ADAS라는 연구분야를 정립하고, 그걸 실현하기 위해 Meta Agent Search라는 방법론을 제안했는데, 이건 메타 에이전트가 코딩을 통해 에이전트를 만들고 개선해나가는 방법이라고 함.
그렇게 만들어진 에이전트는 다양한 도메인에서 SOTA를 찍는 우수한 성능을 보였으며, 심지어 모델과 도메인이 바뀌어도 성능이 강건하게 유지되었다면서 수작업 엔지니어링보다 자기들의 학습되는 방식이 우월하다고 어필.

## 1. Introduction

파운데이션 모델이 빠르게 발전하면서, 단순 LLM이 아니라 여러 도구와 시스템으로 구성된 에이전트로 발전시켜 현실의 더 복잡한 과제들을 해결할 수 있도록 만들어주는 추세임.
좋은 에이전트를 만들기 위해 그 동안 CoT기반의 계획 및 추론, 메모리구조, 도구사용과 자기성찰같은 훌륭한 방법론들이 제안됐지만, 결국 크게보면 이런 방법론과 구조도 사람이 설계하는 수작업 특성에 해당해서 궁극적으로는 자동으로 학습되는방식으로 전환되는것이 우월할거라고 함.

기존연구중에도 ADAS에 해당하는 방법이 있긴했는데, 프롬프팅을 고치는쪽에만 집중하는 방법이라서 에이전트의 workflow를 바꾸거나 하지 못하는 상당히 제한적인 방법이었다고 함.
그래서 저자들은 에이전트를 튜링완전하게 코드로 개선해나가는 방법을 제시하는데, 훨씬 표현력이 넓은 방법임.

![논문 Figure 1: Meta Agent Search 개요 - 메타 에이전트가 새 에이전트를 코드로 만들고 평가해 아카이브에 추가하는 루프와 발견된 에이전트 예시](/assets/img/ai_paper_reviews/ADAS/adas-fig1.png)

Meta Agent Search라고 하는데, 메타 에이전트가 새로운 에이전트를 제작하고 평가하는 루프를 계속 돌면서 점진적으로 더 좋은 에이전트를 만들어나가는 방법론임.
근데 성능만 쫓는게 아니라 흥미로움도 추구하도록 해서 참신하거나 가치있는 에이전트를 많이 만듦.

성능평가는 ARC나 GSM8k 등의 전통적인 쉬운 LLM 벤치마크에서 하는데, 자기들게 SOTA에 비해 성능이 20% 이렇게 늘었고 강건했다고 함.
근데 현실의 문제를 풀려고 만든 에이전트를 이런 간단한 QA에서 평가하는게 상당히 짜친다고 생각했고, 마지막에 저자들도 그 점을 인정함.

## 2. **Automated design of agentic system**

ADAS라는 에이전트 시스템 자동설계분야의 정의는 아직 합의되지 않았기때문에, 자기들이 정의함.
ADAS를 탐색알고리즘을 이용해 탐색공간전반에서 평가함수를 최적화하는 최적화문제로 정의.

![논문 Figure 2: ADAS의 세 가지 핵심 요소 - Search Space, Search Algorithm, Evaluation Function](/assets/img/ai_paper_reviews/ADAS/adas-fig2.png)

탐색공간은 메타에이전트가 조작할 수 있는 에이전트의 범위이고 여기서는 과거의 프롬프트에 비해 훨씬 넓은 탐색공간을 다루게 됨.

탐색 알고리즘은 경사하강법이나 강화학습같은 기존의 전통적인 최적화 알고리즘을 쓰지않고, 그냥 메타 에이전트인 LLM을 사용함.

평가함수로는 검증데이터셋의 정확도를 사용함.

ARC는 이렇게 패턴을 보고 결과를 유추하는 IQ 테스트같은 벤치마크인데, 매 문제 패턴이 달라서 제시된 few-shot 예시들을 보고 그때그때 잘 유추해내야하는 상당히 어려운 벤치마크였음.
26년 기준으로는 뚫어버렸지만, 예전에는 한자릿수 성적 나오는 통곡의 벽이었다고 함.

실험설정으로는 너무 어렵기때문에 5x5 이하의 문제들만 필터링해서 사용했고, 메타 에이전트로는 GPT-4를 에이전트의 모델로는 GPT-3.5를 사용했음.
아마 이따가 포화된 GSM8k같은 벤치마크에서 개선을 보여주기 위해 일부러 GPT-3.5같은 멍청한모델을 쓴듯?
또, 에이전트 개발 루프는 25번 돌림.

경쟁상대인 베이스라인으로는 CoT, CoT-SC, Self-Refine 등의 쟁쟁한 에이전트 방법론들을 사용했는데, 얘네들을 자기 아카이브 초기 시드로 사용했다고 함.
아니 그럼 불공평한거 아니야? 했는데, 부록에서 아무 시드데이터도 안줬을때도 성능이 비슷하게 나왔다고 함.
근데 그렇다고 한들, 다른 방법론들과 달리 이 벤치마크의 검증데이터를 이용해서 맞춤설계되었기 때문에 불공정한면은 있는듯?

![논문 Figure 3: (a) ARC에서 iteration에 따른 Meta Agent Search의 held-out 정확도와 baseline 비교, (b) 발견된 최고 성능 에이전트의 구조도](/assets/img/ai_paper_reviews/ADAS/adas-fig10.png)

어쨌든 ARC에서 실험해보니 iteration을 반복하면서 점점 성능이 오르더니 결국 다른 뛰어난 SOTA 방법론들을 압도하는 결과가 나왔음. 
결과적으로 가장 성능이 뛰어난 에이전트는 fig3(b) 같은 구조였는데, 에이전트5개가 CoT를 하고 복잡하게 평가를 하고 수정하고 또 그걸 앙상블 하는 식의 아주 복잡한구조였고, 인간이 짜기에는 매우 귀찮은 형태였지만 Meta agent search는 저런 구조도 알아서 잘 조립해서 만들었다는 이야기.
정성적으로 들여다보니까 이전 itertation들에서 발견한 내용들을 아카이브에 저장했다가 그걸 발판삼아서 점점 발전시켜나가는식으로 개방형 탐색의 흔적이 보였다고 함.

### 4.2 Reasoning and problem solving tasks

![논문 Table 1: 독해, 수학, multi-task, 과학 도메인에서 Meta Agent Search와 수작업 에이전트들의 성능 비교](/assets/img/ai_paper_reviews/ADAS/adas-fig11.png)

전통적인 벤치마크 DROP, MMLU, MSGM, GPQA들을 통해 일반적인 QA능력을 테스트함.
여기서도 자기들 방법이 좋은 결과를 보였는데, 수학과 독해문제에서는 높은 성능향상을 보인데 반해 나머지 분야에서는 성능향상이 밋밋했음.
그걸 보고 아마 지식 자체가 모자란건 agentic workflow로 커버하긴 어렵지만 실수나 논리비약같은건 잘 잡아내서 그런것같다고 분석함.
그리고 Prompt optimization(OPRO)가 초반에 말한 프롬프트에만 집중하는 ADAS인데, 결과를 보면 역시 코드도 바꾸는 meta agent search보다 훨씬 못한걸 알 수 있음.

### 4.3 Generalization and transferability

![논문 Table 2: MGSM에서 찾은 상위 에이전트를 다른 수학 및 비수학 도메인으로 전이했을 때의 성능](/assets/img/ai_paper_reviews/ADAS/adas-fig12.png)

이 실험결과가 좀 인상적이었음.
특정 도메인에서 meta agent search로 찾은 최적 에이전트를 다른 도메인에서 써보는 훈련이었는데, 놀랍게도 다른 도메인에서 썼을때도 베이스라인들보다 높은 성능을 냈음.
원래 이 논문의 방법론을 보면서 다른애들은 벤치마크에 대해 정보없이 설계된 에이전트 방법론인데 반해 얘는 벤치마크의 검증데이터를 이용해서 맞춤설계되었기 때문에 불공정하다고 생각했는데, 이 결과를 보니 그게 아니라 범용적이고 문제해결의 본질에 가깝게 최적화되는거지, 맞춤설계되고 과적합된건 아닌것같음.
